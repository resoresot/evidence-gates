# ADR 0002: LLM の判定は、フックが文脈を組み立てて Claude Code の CLI を呼ぶ

- 状態: 採用(2026-11-19)
- 関係するファイル: `gates/llm_judge.py`、`gates/completion_gate.py`(`prefilter`、`llm_checks`)

## 状況

done と ask を LLM に判定させるには、「最後の編集のあとに何を実行したか」を LLM が見られる必要がある。
Claude Code には LLM で判定するフック(`type: "prompt"`)があるが、渡されるのは最後の返答だけで、ターンの中の行動は見えない。

## 決定

通常のフック(Python)が会話の記録を読み、依頼・行動の一覧・最後の返答をまとめて、Claude Code の CLI(`claude -p`)を呼ぶ。

- システムプロンプトを差し替え、ツール・フック・設定・MCP・会話の保存をすべて外して呼ぶ。判定役が別の作業を始めたり、このフックが入れ子で呼ばれたりしないようにするため。
- 判定の基準の文(`RUBRIC`)は、本番と評価で同じものを読み込む。評価で測った物と本番で動く物がずれないようにするため。
- 安い絞り込み(`prefilter`)を通ったターンだけ呼ぶ。
- 呼べなかったとき(CLI が無い、時間切れ、答えの形が違う)は規則の判定に戻る(fail-open)。呼んだかどうか・失敗・時間・費用は `events.jsonl` に残す。

## 検討した案

| 案 | 退けた理由 |
|---|---|
| `type: "prompt"` のフック | 行動が見えないので、done は判定できない |
| Anthropic の API を直接呼ぶ | API キーの設定がもう 1 つ要る。Claude Code の利用者は CLI の認証を既に持っている |
| 規則が止めたときだけ LLM に聞く(安い) | 評価で、規則が見逃した場面を拾えず、規則だけより悪かった |
| 行動の一覧を切らずに全部渡す | 長いターンで費用が膨らむ。代わりに、各コマンドの先頭と末尾を残し、確認にあたるコマンド名を必ず添える(先頭 160 字で切った最初の版は、末尾の確認が見えず、正解 9 件中 7 件を誤らせた) |

## 見直す条件

- `type: "prompt"` のフックに会話の記録が渡るようになったとき。
- 1 回あたりの費用や待ち時間が、利用者にとって問題になる大きさになったとき。
