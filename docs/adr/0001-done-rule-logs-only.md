# ADR 0001: 「確かめずに完了」の規則は、既定では止めずに記録だけにする

- 状態: 採用(2026-11-19)
- 関係するファイル: `gates/completion_gate.py`(`evaluate`、`EVIDENCE_GATES_DONE_RULE`)、[eval/RESULTS.md](../../eval/RESULTS.md)

## 状況

`completion_gate` の done は、このプラグインを作るきっかけになった判定でした。
最後の編集のあとにコードを動かしていないのに「完了」と言ったら止める、という規則です。
作者の記録 178 件にラベルを付けて測ると、次のことが分かりました。

- 確かめずに「完了」と言った場面は 178 件中 1 件だけだった(強いモデルでは、この失敗はもうまれ)。
- 規則は全ターンの約 5% で止めていて、標本で止めた 28 件は正解ではすべて不要だった。
- 一番多い原因は、編集とその確認を 1 つのシェルコマンドの中で続ける書き方。規則にはコマンドの中の順番が読めない。

## 決定

規則による done の判定は、既定では止めずに `events.jsonl` に `done_shadow` として記録するだけにする。
止めたい場合は `EVIDENCE_GATES_DONE_RULE=block` を設定する。LLM の判定を使う設定(`EVIDENCE_GATES_JUDGE`)では、LLM の判定で止める。

## 検討した案

| 案 | 退けた理由 |
|---|---|
| 規則のまま止め続ける | 約 5% のターンで、不要なやり直しを AI にさせ続ける。止めた場面がほぼ全部誤りなら、利用者はゲートを無視するか外す |
| 規則を直して読める書き方を増やす | 28 件の原因は 4 種類に散らばっていて(コマンドの中の順番、シェル変数に隠れた書き先、コミット、読み違え)、どれもシェルの意味の解釈が要る。直すたびに別の書き方で誤る見込みが高い |
| done の判定を消す | 弱いモデルや別の使い方では、この失敗は今も起きうる。記録を残せば、発火率の変化で気づける |
| 既定で LLM に判定させる | 利用者に API の費用(1,000 ターンあたり約 8 ドル)と待ち時間(約 3 秒)を、断りなしに負わせることになる |

## 結果

- 規則の done は、止めずに件数だけを数え続ける(影の運転)。
- このプラグインの見出しの機能を、自分の測定で既定から外したことになる。README の冒頭にもそのとおり書く。

## 見直す条件

- 弱いモデルで使い、記録で確かめずに「完了」が増えたとき。
- 規則が、編集と確認を同じコマンドで続ける書き方を読めるようになったとき。
